# Place Space

Self-hosted моніторинг оголошень. Пайплайн уже пише в SQLite, а SvelteKit показує стрічку, картку оголошення і стан перевірки.

```text
fetch → normalize → observation → exact dedup → filter → diff
```

Джерело цього зрізу — LUN. Пошук не має публічного API; сторінка містить картки оголошень як JSON, тож адаптер читає їх напряму, без браузера. OLX, Flatfy, HTTP API і Svelte — після того, як цей ланцюжок стабільно повторюється.

## Інтерфейс

`serve` і показує API, і сам перевіряє збережені пошуки. Інтервал береться з пошуку, типово 10 хвилин. Окрема команда для оновлення не потрібна.

```bash
go run ./cmd/placespace serve
```

```bash
cd web && npm install && npm run dev
```

Відкрийте http://localhost:5173. Відкрита сторінка сама перечитує дані кожні 30 секунд. `placespace run` лишається, якщо перевірку треба крутити без інтерфейсу.

## Додаток

Подвійний клік відкриває власне вікно і сам перевіряє пошуки. На Windows це `place-space.exe`, на Mac — `Place Space.app`. База з’являється поруч із програмою, у папці `data`: для Mac це поруч із `.app`, не всередині нього. Закриття вікна зупиняє програму. Журнал пишеться в `data/place-space.log`.

Посилання на оголошення відкривається у звичайному браузері. `serve` без вікна лишається на http://127.0.0.1:8080 — так зручно розробляти інтерфейс.

Збірка йде в GitHub Actions (`.github/workflows/desktop.yml`) на агентах Windows і macOS. Запуск вручну дає обидва файли у вкладці Actions. Тег на кшталт `v0.1.0` публікує реліз. Mac-збірка для Apple Silicon. Програма не підписана, тож перший запуск на Mac може вимагати правий клік і «Відкрити». На Windows потрібен WebView2, він уже є у Windows 10 і 11.

Локально упакувати інтерфейс у бінарник:

```bash
cd web && npm run build
go build -tags ui -o place-space ./cmd/placespace
```

## Запуск перевірки джерел

```bash
go run ./cmd/placespace poll \
  --city "Кам'янець-Подільський" \
  --price-max 20000 \
  --rooms-min 2
```

Команда створює SQLite у `data/place-space.db`, зберігає Watch і друкує JSON у stdout. Лог іде в stderr.

Повторний запуск тих самих оголошень дає `new: 0`. Зміна ціни дає `changed` і новий рядок у `listing_observations`. Відхилені оголошення не ховаються: у кожному є причина, наприклад `price: 24500 > 20000`.

```bash
go run ./cmd/placespace status
go run ./cmd/placespace run
```

`run` бере список Watch на старті і перевіряє їх, доки процес не зупинять. Зміну критеріїв уже збереженого Watch він побачить на наступній перевірці. Новий Watch потребує перезапуску.

Інші міста, яких немає у вбудованому списку, можна передати шляхом LUN:

```bash
go run ./cmd/placespace poll --city /rent/kyiv/flats --price-max 30000
```

Будинки: `--property apartment,house`.

## Межі цього зрізу

- Точна дедуплікація: `source + externalID`, плюс зв'язок за канонічним URL. Оголошення не зливаються.
- Фільтри детерміновані. Невідома ціна, площа чи кімнати не проходять умову, яка їх вимагає.
- Відсутність оголошення на сторінці ще не означає, що воно зникло.
- Зберігається не більше `--pages` сторінок (типово 5) на кожен тип житла.
- Немає Telegram, автентифікації і семантичного matching.
